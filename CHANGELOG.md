## [Unreleased]

### Highlights

- specification-workflow-spec is now the single source of truth for all default spec workflows (~25 profiles); VisionStudio's divergent local catalog was retired
- An initiative's spec workflow can be changed after creation (initiative update --workflow), and the Initiative page adapts to whichever workflow is selected
- AWS Working Backwards profiles (aws-one-way-door, aws-two-way-door) aligned to the authoritative visionspec D2 flows, with execution phases and corrected synthesis DAGs (upstream)
- First web mutation: a New Initiative button on the dashboard creates an initiative with catalog workflow selection (POST /api/initiatives)

### Added

- POST /api/initiatives — the API's first mutation endpoint (validates ID/title/workflow against the catalog, 409 on duplicates); dashboard gains a New Initiative button and modal with workflow dropdown, per-workflow required-docs preview, and type-driven workflow defaults, landing on the new initiative's Definition tab
- initiative update --workflow <id> — switch an initiative's spec workflow after creation, validated against the catalog; keeps the synthesis/eval workflow-selection record in step
- workflow sync — idempotent sync of the DB workflow index from the specification-workflow-spec catalog, remapping initiatives off retired IDs (pbhq-standard→pbhq-lite) and deleting retired unreferenced rows (workflow seed deprecated as alias)
- Spec-file roles: /api/spec-files classifies every file as required/optional/extra against the initiative's workflow and returns files in workflow order; the UI badges extras
- Workflow detail in /api/specs: sequence and phases per workflow, sourced from the catalog, powering a dynamic per-workflow diagram on the Initiative page
- workflowId in /api/execution initiatives (closing an existing runtime/type mismatch) and a read-only workflow chip on the Initiative page
- quick-fix workflow profile upstream in specification-workflow-spec (extends pbhq-lite; ROADMAP-only required)
- DeleteSpecWorkflow store method (interface, doltstore, memstore)
- Template and rubric viewing from the Initiative Definition tab: clicking a document in the workflow diagram (or the Template/Rubric buttons in the spec viewer) opens a modal showing the authoring template (with its Leadership Principle guidance) and the LLM-as-a-Judge rubric (categories, weights, pass/partial/fail criteria), served from the embedded catalog via GET /api/workflows/{id}/specs/{type}

### Changed

- Default workflow by initiative type: maintenance/refactor/migration→quick-fix, feature/compliance/default→pbhq-lite (pbhq-standard retired; canonical upstream pbhq-lite requires all four docs)
- workflow list/get read from the catalog (with sequence/phase detail) instead of DB rows; deterministic execution-sequence ordering
- InitiativeDetail and SpecViewer derive spec sets, progress denominators, tab order, and the workflow diagram from the assigned workflow instead of hardcoded PBHQ Lite
- AWS Working Backwards flows reordered to be PR-first (authentic Amazon practice): the human-authored Press Release is the founding artifact in both aws-one-way-door and aws-two-way-door; MRD (product) and OpportunitySpec (feature) demoted to optional post-FAQ deepening; product/feature difference expressed as ceremony (one-way vs two-way door: 6-pager required vs optional). Upstream profiles, visionspec D2 diagrams/SVGs, and aws.md updated together. Profiles also gain the authentic ceremony machinery: iteration_trigger on the PR/FAQ, prfaq_review gates, a required decision_meeting gate for aws-one-way-door, an evidence-appendix section in the press templates (mockups/demos labeled by what they prove), and spike-backed feasibility prompts in the FAQ templates.
- AWS Working Backwards profiles renamed by Amazon's actual selection criterion — decision reversibility: aws-product→aws-one-way-door, aws-feature→aws-two-way-door (workflow sync remaps existing initiatives). Scale and door decoupled: both deepening docs (MRD and OpportunitySpec) are optional in both profiles — the door sets the ceremony, the scale picks the tool.
- Amazon Leadership Principles infused into the AWS door workflows (sourced from amazon.jobs and the Jassy video transcripts): full 16-principle set with canonical reference in both profiles' methodology metadata; LP guidance in the press/FAQ/6-pager templates (canonical FAQ vetting questions, Kozmo economic-sustainability lesson, personal-money test, hard-to-fake-details narrative rationale); LP-grounded rubric categories (press economic_sustainability, FAQ disconfirmation_rigor, 6-pager ownership_horizon) and door-specific decision-reversibility criteria in the PRD rubrics.

### Fixed

- pbhq-lite profile's execution block silently failed to parse upstream (workflow: vs execution: YAML key) — no workflow had ordering data at runtime
- aws-two-way-door synthesis guidance was silently dropped (GetSynthesisGuidance now falls back to prompt_context)
- aws-one-way-door synthesis gaps vs the reference D2: missing ird←trd rule, trd missing mrd source, tpd missing uxd source, narrative-6p sourced from faq instead of prd
- aws-two-way-door required a 6-pager narrative that the reference feature flow does not include (now optional)

### Documentation

- Spec Workflows section in the dashboard guide (selection, switching, required/optional/extra semantics); quickstart workflow commands; CLAUDE.md single-source-of-truth convention

### Tests

- Upstream D2-conformance and parse-regression suite (pkg/workflows/execution_test.go); SyncFromCatalog/Resolve/SpecFileName unit tests; catalog-based buildSpecsResponse test

## [v0.5.0] - 2026-08-10

### Highlights

- The pivot: a new Go CLI + web dashboard (`visionstudio`) for cross-repository roadmap execution — Programs -> Initiatives -> Phases -> RMIs, backed by Dolt — alongside the existing spec-authoring system, superseding the Electron desktop app and cmd/daemon as the primary surface
- Renamed the binary and module entry point from `vistudio` to `visionstudio` (breaking)
- One-command startup (`visionstudio app start`), an embedded web SPA (go:embed, no external files needed), and actionable DB-down diagnostics instead of raw driver errors
- Programs, initiatives, and now individual initiatives can each be hidden from the dashboard, with hiding a program cascading to its initiatives everywhere they're listed
- Real path-traversal fixes, not just lint suppressions: the spec-files endpoint and 12 separate CodeQL alerts across cmd/daemon, closed using a validation pattern upstreamed to the shared grokify/mogo library (ValidatePathComponent/JoinSecure/FindFirstExistingSecure) rather than duplicated locally
- Full documentation overhaul: README/installation/quickstart now lead with the visionstudio CLI, the Electron/daemon path is explicitly marked legacy, and six new dashboard user-guide pages cover every panel

### Security

- Upstreamed ValidatePathComponent (allowlist regex) and JoinSecure (filepath.Rel/filepath.IsAbs containment check) to github.com/grokify/mogo's os/osutil, rather than a repo-local package -- verified against a live CodeQL scan that this specific idiom is what the go/path-injection query recognizes as a sanitizer, unlike a strings.HasPrefix check wrapped in a helper function ([`05ca077`](https://github.com/ProductBuildersHQ/visionstudio/commit/05ca077))
