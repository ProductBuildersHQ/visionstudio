## [v0.7.0] - 2026-10-01

### Highlights

- Cloud multi-tenancy groundwork — an optional, inert-for-local tenant_id mixin on every shared entity, plus a Postgres-backed store (NewPostgres/NewPostgresFromConn) so the same Ent-backed store.Store runs over managed Postgres with pool + Row-Level Security for a cloud, and over Dolt/MySQL locally; local stays a single implicit tenant with no behavior change
- Auto-assigned RMI/initiative IDs — rmi create and initiative create allocate the next free ID for a repo/project slug when --id is omitted, and new rmi next-id / initiative next-id commands print the next ID(s) without creating anything, so a ROADMAP.md can be filled with correct IDs and cross-references before import
- RMI keyword search — rmi list --grep searches RMI IDs and titles (case-insensitive) across every initiative and repository
- Cloud-to-local pull — fetch and fast-forward-merge a cloud tenant's branch into the local database, with fast-forward-only safety on both push and pull

## [v0.6.0] - 2026-08-17

### Highlights

- Spec workflow single source of truth — specification-workflow-spec's catalog (~25 profiles) is now the only workflow definition source; VisionStudio's divergent local catalog was retired, a workflow can be switched after creation, and the Initiative page adapts to whichever workflow is assigned
- Authentic AWS Working Backwards — aws-one-way-door/aws-two-way-door profiles reordered to be PR-first per actual Amazon practice and infused with the 16 Leadership Principles, alongside the dashboard's first web mutation (New Initiative creation, POST /api/initiatives)
- Registry & RMI lifecycle CLI — repository records can be updated, archived with supersession, removed, and health-checked (registry doctor); RMIs can be bulk-reassigned across repositories as one auditable operation
- Release tracking system — a Release entity with initiative/RMI/repository edges, a full release CLI (plan/record/list/show/attach/detach/delete/backfill-match), a changelog gate, an unshipped-initiatives queue, and CHANGELOG.json/git-tag/GitHub-Releases ingest — the very system used to prepare this release
- Registry org/person/visibility modeling — Organization and Person entities, GitHub-derived repository visibility, and a publicrail export safety rail gating what any public roadmap view can ever show
- Reversible initiative lifecycle — an initiative can reopen to any earlier pipeline status as scope evolves, with later-stage lifecycle timestamps cleared so history stays truthful
- VisionStudio Cloud groundwork (dogfood-only) — local tenant-assignment config and a whole-database sync command over godolt
- initiative sweep — finds initiatives whose RMI completion has outrun their recorded lifecycle status, verified against real per-repo git state across every repository an initiative's RMIs touch (not just its home repo)
- Dashboard By Status view — the initiative portfolio grouped into pipeline-ordered columns (proposed through cancelled), for managing WIP at a glance alongside the existing By Program grouping
- Progress bars distinguish cancelled RMIs (red) from genuinely pending ones (blank), and show green once completed + cancelled account for the whole bar -- previously a fully-resolved initiative with some cancelled work still read as "in progress" (blue) with an indistinguishable gray tail
- visionstudio app restart -- replaces a stale UI+API server (e.g. serving an old binary after a rebuild) in place, without hunting down and killing a PID by hand
- RMI.Origin: structured tracking of how an RMI's scope was identified (spec, implementation, acceptance_testing, discussion) -- generalizes the ad hoc "found during acceptance testing" description-phrase convention into a real, queryable field, and a telemetry foundation for how complete specs actually are at project start
- visionstudio release candidates --repo <repo-id>: repo-first release readiness, complementing initiative sweep's initiative-first direction -- for a repo about to be released, find every touching initiative and whether it's ready/partial/not_ready/already_attached
- Attached releases are now visible on initiatives -- initiative get prints a Releases: repo@tag section, and the Initiative Detail dashboard page shows a "Released in:" chip row -- surfacing data the Release entity already recorded correctly (one tag per repo for multi-repo initiatives) but nothing displayed

## [v0.5.0] - 2026-08-10

### Highlights

- The pivot: a new Go CLI + web dashboard (`visionstudio`) for cross-repository roadmap execution — Programs -> Initiatives -> Phases -> RMIs, backed by Dolt — alongside the existing spec-authoring system, superseding the Electron desktop app and cmd/daemon as the primary surface
- Renamed the binary and module entry point from `vistudio` to `visionstudio` (breaking)
- One-command startup (`visionstudio app start`), an embedded web SPA (go:embed, no external files needed), and actionable DB-down diagnostics instead of raw driver errors
- Programs, initiatives, and now individual initiatives can each be hidden from the dashboard, with hiding a program cascading to its initiatives everywhere they're listed
- Real path-traversal fixes, not just lint suppressions: the spec-files endpoint and 12 separate CodeQL alerts across cmd/daemon, closed using a validation pattern upstreamed to the shared grokify/mogo library (ValidatePathComponent/JoinSecure/FindFirstExistingSecure) rather than duplicated locally
- Full documentation overhaul: README/installation/quickstart now lead with the visionstudio CLI, the Electron/daemon path is explicitly marked legacy, and six new dashboard user-guide pages cover every panel

### Security

- Upstreamed ValidatePathComponent (allowlist regex) and JoinSecure (filepath.Rel/filepath.IsAbs containment check) to github.com/grokify/mogo's os/osutil, rather than a repo-local package -- verified against a live CodeQL scan that this specific idiom is what the go/path-injection query recognizes as a sanitizer, unlike a strings.HasPrefix check wrapped in a helper function ([`11a5532`](https://github.com/ProductBuildersHQ/visionstudio/commit/11a5532))
