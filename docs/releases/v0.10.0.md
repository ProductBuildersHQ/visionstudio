# v0.10.0 Release Notes

**Release Date:** 2026-08-16

VisionStudio v0.10.0 closes `INIT-VISIONSTUDIO-011`'s sixth and final phase: `visionstudio release candidates`, the repo-first counterpart to `initiative sweep`. Proposed directly by the user while discussing how an agent actually works when releasing a specific repo. Like the releases before it, this one is prepared and documented but **not yet tagged**.

## Highlights

- **`visionstudio release candidates --repo <repo-id>`** — `initiative sweep` answers "is this initiative done?" starting from the initiative. Releasing a repo needs the inverse: "which initiatives touching this repo are ready to move to released/closed alongside it?" A repo's RMIs are usually a subset of several different initiatives' full scope, so those are genuinely different questions.

## What's New

`release candidates` lists every non-terminal initiative with at least one RMI in the given repo and classifies it:

| Verdict | Meaning |
|---|---|
| `ready` | every RMI across every repo the initiative touches is done — a full close candidate |
| `partial` | this repo's RMIs are done, but the initiative still has open work in other repos — record the release against it, don't close yet |
| `not_ready` | this repo still has open work |
| `already_attached` | a prior release of this repo already lists this initiative |

Report-only, same discipline as `sweep` — it never calls `release record` or `initiative transition` itself.

Live-tested against `visionstudio` itself: correctly found `INIT-VISIONSTUDIO-003`/`-007` as `ready` (already known from a manual sweep two releases ago) plus a new one, `INIT-DEVXREPORTS-001`. It also correctly flagged `INIT-VISIONSTUDIO-001` as `already_attached` despite 0% RMI completion — an early, broad release attachment from before per-RMI tracking was consistent. Accurately reported, not a bug in the new command.

## Documentation

`CLAUDE.md` gained guidance on when to reach for `sweep` (initiative-first) vs. `candidates` (repo-first): use `candidates` when releasing a specific repo, since its RMIs are usually a subset of several initiatives' full scope. The dashboard guide's "Finding initiatives ready to advance" section now cross-references both.
