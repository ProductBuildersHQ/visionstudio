# v0.11.0 Release Notes

**Release Date:** 2026-08-16

VisionStudio v0.11.0 closes `INIT-VISIONSTUDIO-011`'s seventh and final phase: release visibility on initiatives. Proposed directly by the user, who asked whether VisionStudio could log the release tag an initiative shipped in — the answer turned out to be that the data model already handled it correctly, including the multi-repo case; it just wasn't shown anywhere. Like the releases before it, this one is prepared and documented but **not yet tagged**.

## Highlights

- **Attached releases are now visible on initiatives** — `initiative get` prints a `Releases:` section, and the Initiative Detail dashboard page shows a "Released in:" chip row, surfacing data the `Release` entity already recorded correctly (one tag per repo for multi-repo initiatives) but nothing displayed.

## What's New

`Release` is repo-scoped (`repo@tag`) with an M2M edge to initiatives — an initiative attached to releases from three different repos (like `INIT-AGENTPROTOCOLS-001`, via `agent-protocols`, `mcp-google`, and `omniskill`) already worked correctly at the data layer. The gap was display:

- `GetInitiativeDetail` gains a `Releases` field (`svc.ListReleases`)
- `initiative get <id>` prints a `Releases:` section — one `repo@tag (date)` line per attached release
- `ExecutionResponse` (both dual-struct API layers, regenerated schema/Zod/TS) gains a `releases` array
- `InitiativeDetail.tsx` shows a "Released in:" chip row in the header, linked to the release URL when one was recorded

## Documentation

Adding the new `APIRelease` type surfaced a real gotcha, now in `CLAUDE.md`: a brand-new top-level `apitypes` struct needs registering in **two** places — `pkg/apitypes/gen/main.go`'s type list (or no `.schema.json` is emitted) and, separately, `web/scripts/generate-types.mjs`'s `schemaNames` array, which is **not** auto-discovered from the schema directory. Missing the second one lets `generate:types` succeed while silently producing no TypeScript export, failing later as an opaque `Module has no exported member` error in `compat.ts`.
