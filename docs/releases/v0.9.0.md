# v0.9.0 Release Notes

**Release Date:** 2026-08-16

VisionStudio v0.9.0 closes out `INIT-VISIONSTUDIO-011`'s fifth and final phase: `RMI.Origin`, a structured field tracking how a roadmap item's scope was actually identified. Proposed directly by the user, generalizing the ad hoc "found during acceptance testing" description-phrase convention used in Phase 4 into something real and queryable. Like the releases before it, this one is prepared and documented but **not yet tagged**.

## Highlights

- **`RMI.Origin`** — every RMI now records how its scope was identified: `spec` (the default — in the original PRD/ROADMAP), `implementation` (the agent found it necessary while building another RMI), `acceptance_testing` (a human found it using the shipped result), or `discussion` (proposed directly in conversation). A foundation for telemetry on how complete specs actually are at project start, and whether they can ever be fully complete before implementation and review.

## What's New

- Ent schema field on `RoadmapItem` (`origin`, default `"spec"`, additive migration — verified existing rows backfill correctly rather than landing null)
- `pkg/rmi` gains `Origin` constants and `ValidOrigin`
- Wired through `doltstore`/`memstore` and both dual-struct API layers (regenerated JSON Schema/Zod/TypeScript)
- `--origin` on `rmi create`/`rmi update`, an `ORIGIN` column and `--origin` filter on `rmi list`
- `origin` support on the `rmi_create` MCP tool, so an agent can self-tag `origin=implementation` in the moment it discovers the need — the fourth value, `discussion`, was added because the RMI that built this feature didn't cleanly fit the other three: it was proposed directly by a human in conversation, not derived from testing a shipped artifact or found mid-build

## Documentation

`CLAUDE.md` gained a durable convention: scope discovered after the initial spec is normal, and gets tracked as a new RMI (tagged with its origin) rather than silently folded into an existing RMI or left untracked. The discipline that keeps this from being scope creep: every addition traces to a **concrete finding** the work surfaced, never speculation — "this would also be nice" goes back to the human as a new proposal, not silently added.

## What's Next

- Tagging `v0.6.0` through `v0.9.0` together, once the batch is confirmed ready
- A dashboard-side origin badge/filter, if the CLI-level telemetry (`rmi list --origin acceptance_testing`) proves useful enough to want visually
